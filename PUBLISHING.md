# Publishing to GitHub and the VS Code Marketplace

## One-time: public GitHub repository

The `repository`, `homepage`, and `bugs` fields in `package.json` point at:

`https://github.com/nuanst-one/vscode-browser-tool`

Create that repository as **public** (the Marketplace listing links `LICENSE` and the README from it), then push `main`. History in this checkout is a single initial commit, so the first push is a normal push, not a force-push.

```bash
git remote add origin https://github.com/nuanst-one/vscode-browser-tool.git
git push -u origin main
```

Do not commit `LOCAL-NOTES.md` (gitignored; machine-specific paths) or `*.vsix` (build artifacts).

## One-time: publisher account

1. Go to <https://marketplace.visualstudio.com/manage/publishers> and sign in with the account
   that will own the extension.
2. Create a publisher named **Nuanst One GmbH** (or reuse an existing one).
3. Make sure the `publisher` field in `package.json` matches the publisher **ID** exactly
   (lowercase, no spaces — e.g. `nuanst-one`). If the actual publisher ID differs, update
   `package.json` before packaging; the ID is shown in the marketplace's manage UI.

## One-time: packaging tooling

```bash
npm install            # installs @vscode/vsce (already in devDependencies)
```

## Each release

```bash
npm run build                      # bundles dist/ (also runs via vscode:prepublish)
npx vsce package                   # -> vscode-browser-tool-<version>.vsix
```

`vsce package` validates the manifest (license file, icon, description length, VSIX size,
node_modules included, etc.) and prints warnings to review. The VSIX must stay under 200 MB;
with `node_modules` (Playwright + MCP SDK, ~80 MB unpacked) it lands well under that.

### Dry-run install the .vsix

```bash
code --install-extension vscode-browser-tool-0.3.0.vsix
```

Then in VS Code: **MCP: Show Running Servers** (or the MCP view) — `browser-tool` should
appear, and `npx playwright install chromium` (or set `BROWSER_TOOL_CHANNEL=msedge`) must have
been done on that machine first.

### Publish

```bash
npx vsce publish --allow-proposed-apis browser
```

`vsce` refuses to publish while `enabledApiProposals` includes `browser` unless that
flag is set. It bypasses the local check only. The integrated browser tab still
requires the user to enable the proposal in `argv.json` (see the README).

Generate a PAT at <https://marketplace.visualstudio.com/manage/tokens> with the
`Marketplace Publish` scope, or export `VSCE_PAT` and run the same command
non-interactively.

After publishing, refresh the marketplace page. The extension's `description` (package.json,
≤ 140 chars) is what shows in search results; the full README.md is the listing page.

## Checklist before publishing

- [ ] `publisher` in `package.json` matches the real publisher ID
- [ ] Public repo exists at the `repository` URL (`vsce` links `LICENSE` from it)
- [ ] `version` bumped in `package.json` and a `CHANGELOG.md` entry added
- [ ] `LICENSE` file present and `license` field set
- [ ] `README.md` is the public listing — no internal URLs or paths
      (`LOCAL-NOTES.md` is gitignored and excluded from the VSIX)
- [ ] Screenshot recommended for the listing: open a page, run the `screenshot` tool, and add
      the PNG to README under a "Screenshots" heading (not required, but strongly
      recommended by marketplace curation)
- [ ] `icon.png` present (128×128, generated by `npm run icon`)
- [ ] No secrets in repo/VSIX (`npx vsce ls` lists exactly what will be shipped)
- [ ] Publish with `npx vsce publish --allow-proposed-apis browser` so the `browser`
      proposal is allowed through vsce's check. Packaging a `.vsix` does not need the flag.

## Open VSX (optional)

The same `.vsix` can be published to <https://open-vsx.org> for non-Microsoft clients
(Codium, VS Code forks):

```bash
npm i -D ovsx
npx ovsx publish vscode-browser-tool-0.3.0.vsix --pat <OPENVSX_PAT>
```

Open VSX requires an OSI-approved license — MIT is accepted.
